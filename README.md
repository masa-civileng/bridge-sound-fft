# 橋梁打音・周波数分析

橋梁などの打音をブラウザで収録し、波形・FFT振幅スペクトル・打撃ごとの指標を確認する試作アプリです。別に収録したハンマーの入力データ（CSV）を読み込むと、打音と打撃力の**振幅スペクトル比**も表示できます。

**[アプリを開く](https://masa-civileng.github.io/bridge-sound-fft/)** ｜ [ソースコード](https://github.com/masa-civileng/bridge-sound-fft)

インストールは不要です。iPhone、Android、Windowsのブラウザから利用できます。マイク録音にはHTTPSとブラウザでのマイク許可が必要です。端末やブラウザによって録音機能の動作は異なります。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 打音の取得 | マイク録音、音声ファイルの読み込み、再生、モノラルWAV保存 |
| 波形・FFT | 波形上で分析位置を選択し、Hann窓を用いた振幅スペクトルとピーク周波数を表示 |
| 打撃の比較 | 打撃候補を検出し、ピーク周波数と低域／高域のスペクトルエネルギー比を一覧表示 |
| 健全基準 | 選択した打撃の低域／高域比の中央値を基準に、各打撃の比を表示 |
| ハンマー入力 | 時刻・力の2列、または力のみの1列のCSVを読み込み、打撃候補を選択 |
| 周波数応答比 | 共通の周波数列で `|打音スペクトル| / |ハンマー入力スペクトル|` を表示 |
| データ保存 | 打音・ハンマーの生データ、両者の振幅スペクトル、打撃指標、周波数応答比をCSVで保存 |

## 使い方

### 打音を分析する

1. [アプリ](https://masa-civileng.github.io/bridge-sound-fft/)を開き、**「録音開始」**を押してマイクを許可します。既存の音声を使う場合は**「音声を読み込む」**を選びます。
2. 打撃後に**「停止」**を押します。必要に応じて**「WAV保存」**や**「打音の生データCSV」**を押します。
3. 波形をタップして分析位置を選択します。**FFT点数**と表示上限を設定し、グラフや**「打音の振幅スペクトルCSV」**を確認します。
4. 複数の打撃を比較するときは**「打撃を検出・分析」**を押します。既知の健全部で測った打撃を**「健全基準」**にチェックし、基準比を確認します。**「指標をCSV保存」**で表を保存できます。

打撃の検出感度や分析窓を変えたときは、**「打撃を検出・分析」**をもう一度押してください。

### ハンマー入力との振幅比を求める

1. 打音を録音するか、音声ファイルを読み込みます。
2. ハンマーのCSVの**形式・列番号・必要な場合はFs**を指定してから、**「ハンマーCSVを読み込む」**を押します。
3. ハンマーの**FFT点数**と比較する**打撃**を選び、打音の波形で対応する打撃位置をタップします。両デバイスの時刻は自動同期しないため、対応する打撃を確認してください。
4. **「周波数応答比を計算」**を押し、グラフと共通の周波数刻み `df` を確認します。**「結果CSV」**で数値を保存できます。

### ハンマーCSVの形式

CSV、タブ区切り、セミコロン区切りの数値データを読み込めます。見出し行は読み飛ばします。時刻と力の列は**1から始まる列番号**で指定してください。

```csv
time_s,force_N
0.0000,0
0.0001,0.2
0.0002,1.1
0.0003,4.8
0.0004,8.0
0.0005,4.1
0.0006,1.0
0.0007,0.1
0.0008,0
```

上の例は**「時刻：秒」**、時刻列 `1`、力列 `2` です。時刻がミリ秒なら**「時刻：ミリ秒」**を選びます。時刻がサンプル番号の場合は**「時刻：サンプル番号」**、1列だけの場合は**「力のみ」**を選び、測定したサンプリング周波数を**「Fs（番号／1列時）」**に入力してください。時刻列を使う場合は時刻差からFsを求めるため、等間隔のデータを用意してください。サンプリング間隔が大きく乱れるCSVは読み込めません。

`force_N` という見出しは例です。力の値をNで出力した場合のみ、入力の単位をNとして解釈してください。1列の例では形式を**「力のみ」**にすると力列は `1` に切り替わります。

## 出力ファイル

| ファイル名 | 主な列・内容 |
| --- | --- |
| `bridge-sound-*.wav` | 録音・読み込み後のモノラル音声（16 bit PCM） |
| `audio_raw.csv` | `sample_index,time_s,amplitude`：録音振幅の生データ |
| `audio_amplitude_spectrum.csv` | `frequency_hz,amplitude,amplitude_db,fs_hz,fft_points,df_hz,center_s`：選択位置の1つのFFT窓 |
| `bridge-hit-features.csv` | 打撃番号、時刻、ピーク周波数、低域／高域、健全基準の中央値に対する比、基準への指定 |
| `hammer_raw.csv` | `sample_index,time_s,force_input`：読み込んだハンマー値 |
| `hammer_amplitude_spectrum.csv` | 周波数、振幅、振幅dB、Fs、FFT点数、df、打撃時刻 |
| `audio_over_hammer_frequency_response.csv` | 周波数、ハンマー振幅、打音振幅、その比、df、分析条件、両者の選択時刻 |

CSVの振幅スペクトルにはHann窓を使います。`amplitude_db` は相対振幅から求めた値であり、校正済みの音圧レベル（dB SPL）ではありません。`bridge-hit-features.csv` の低域／高域は、300–1000 Hzのスペクトルエネルギーを1000–5000 Hzのスペクトルエネルギーで割った値です。

## 周波数刻みの合わせ方

ハンマー側の周波数刻みは `df = Fs_hammer / N_hammer` です。アプリは打音側の分析サンプル数を概ね `Fs_audio / df` に合わせたうえで、**Chirp-Z変換**によりハンマー側と同じ周波数 `k × df` で打音スペクトルを評価します。打音側のサンプル数が整数のため通常のFFTでdfが完全一致しない場合も、出力する周波数列は一致します。

比を求める周波数では、ハンマー振幅がそのスペクトルの最大振幅の1%未満なら値を空欄にします。打撃入力がほとんどない帯域の比を数値として扱わないためです。

## 利用上の注意

- 本アプリは**研究・予備調査用**です。損傷の自動判定や不具合の確定は行いません。既知の健全部を含め、同じ対象部材・打撃位置・ハンマー・マイク距離で複数回比較してください。
- マイクが校正されていない場合、打音の振幅は録音振幅の相対値であり、`Pa/N` の伝達量ではありません。端末のマイク特性やブラウザの音声処理設定も結果に影響します。
- 本アプリの「周波数応答比」は**振幅スペクトルの比**です。別デバイスの記録を厳密に同期していないため、複素数の周波数応答関数の位相やコヒーレンスは計算しません。
- 打音・ハンマーのデータはブラウザ内で処理し、アプリから測定データをサーバーへ送信する処理はありません。CSVとWAVは利用者が操作して端末に保存します。

## 動作環境とトラブル対応

- マイク録音はHTTPSの[公開ページ](https://masa-civileng.github.io/bridge-sound-fft/)で試し、ブラウザとOSの両方でマイク利用を許可してください。音声ファイルの読み込みは、マイクが使えない場合にも試せます。
- 音声ファイルはブラウザがデコードできる形式を利用してください。WAV、M4A、MP3などの対応状況は端末とブラウザによって変わります。
- ローカルのHTMLファイルを直接開いた場合には、ブラウザの権限・セキュリティ設定によって録音できないことがあります。公開ページでの利用を推奨します。
- スマートフォンを含む全端末での実機確認は済んでいません。問題があれば、端末・OS・ブラウザ・操作・表示されたエラーを添えて[Issues](https://github.com/masa-civileng/bridge-sound-fft/issues)で報告してください。
